# YSCOT v0.3 架构：房间、课程包、讲师与嵌入能力

> 目标：让课堂后台脱离课件独立运行，能服务 PPT 讲课、实操演练、线下活动；课件变成可替换的课程包；讲师用钉钉登录；对外提供嵌入 API 与 MCP。

## 1. 分层

```
内容层     课程包（zip / 模板 / AI 生成）        宣传页
              ↓
课堂层     房间 Room（状态 + 时间线）  ←—— 大屏 /screen、遥控器 /remote
              ↓
身份层     讲师（钉钉 OAuth）、学员（房间码 + 姓名尾号）、只读大屏 token
              ↓
接口层     REST / SSE / embed.js / MCP
```

**判断标准**：任何功能先问“它属于房间、内容、身份还是接口”，不再往课件页里塞。

## 2. 房间（核心对象）

```
rooms/<code>/
  room.json      # 标题、讲师、助教、创建/关闭时间、状态
  state.json     # 学员、分组、投票、抢答、答题、作业、计时、积分
  events.ndjson  # 课堂时间线（谁在何时做了什么）
  uploads/       # 作业与素材
```

- 房间码 4 位大写字母，避免 0/O/1/I；
- 学员入口 `/join?room=CODE`，扫码进入；
- 讲师入口 `/ops?room=CODE`；
- 大屏 `/screen?room=CODE&t=<screenToken>`（只读）；
- 遥控器 `/remote?room=CODE&t=<remoteToken>`（讲师手机）；
- 旧地址 `/admin`、`/grader` 保留为“默认房间”的别名，不破坏已发链接。

**状态迁移**：现有全局 state 迁到默认房间；接口加 `room` 作用域，逻辑不变。

## 3. 讲师管理（钉钉登录）

参考项目协作工作台的做法：钉钉企业内部应用 OAuth2 授权码 + HMAC 签名 Cookie，零 npm 依赖。

### 3.1 登录流程
1. `/login` 点「钉钉登录」→ `GET /auth/dingtalk` 跳转 `https://login.dingtalk.com/oauth2/auth?...`；
2. 回调 `/auth/dingtalk/callback?authCode=...`：换 `userAccessToken`，取 `contact/users/me`（nick、unionId、openId、mobile）；
3. 匹配讲师表：`unionId > openId > mobile`；
4. 未匹配 → 绑定页（按姓名/手机后四位候选，管理员确认）；
5. 签发 `gtsc_session`（HttpOnly、SameSite=Lax、7 天、HMAC 签名）；
6. 记录登录审计。

### 3.2 角色与权限
| 角色 | 能做什么 |
|---|---|
| 超管 | 讲师管理、所有房间、MCP token、审计 |
| 讲师 | 自己的房间；建/开/关；全部课堂操作 |
| 助教 | 被指派房间的课堂操作，不能建房间与导出 |
| 观察 | 只读（大屏/报告） |

- 组织架构（育钉）：拉部门路径存 `dept`，按部门映射默认角色；已授权组织外的人拒绝登录；
- 首次超管：用环境变量 `ADMIN_DING_UNIONID` 指定，避免空库无法登录；
- **离线兜底**：无外网/无钉钉时，允许 `LOCAL_TEACHER_PASSWORD` 本地登录（仅教室局域网，默认关闭）。

### 3.3 环境变量
```
DINGTALK_CLIENT_ID / DINGTALK_CLIENT_SECRET
DINGTALK_CORP_ID              # 组织校验
SESSION_SECRET                # Cookie HMAC
ADMIN_DING_UNIONID            # 首个超管
LOCAL_TEACHER_PASSWORD        # 可选，离线兜底
```

## 4. 课程包（内容层）

### 4.1 包结构
```
package.zip
  course.json      # 清单
  index.html       # 入口（standalone 模式）
  slides/*.html    # 或 native 模式的分页
  assets/*
```

`course.json` 最小字段：
```json
{
  "id": "pkg-xxx",
  "title": "课程标题",
  "theme": "fenglin",
  "mode": "native | standalone",
  "entry": "index.html",
  "slides": [{"id":"s1","title":"封面"}],
  "capabilities": {"poll": true, "quiz": true}
}
```

- **native**：外层壳提供导航/后台入口，内层只放分页 HTML（壳控制翻页）；
- **standalone**：整页 iframe，课程包自己控制导航（适合 PPT 导出的 HTML）；
- 框架页 `/course?pkg=<id>`：顶部保留导航、房间码、后台入口、全屏；
- 上传后先预览，再发布；保留版本，可回滚。

### 4.2 课程包模板
`packages/template/` 提供：
- `schema.json`（内容 JSON 的字段约束）
- `render.mjs`（确定性渲染：JSON → HTML，不依赖 AI 现场写代码）
- `theme.css`（配色/字体/版式）
- `example.json`

### 4.3 AI 生成课程包（推荐管线）
```
素材（md/docx/大纲）
  → 抽题目录与要点（LLM，输出严格 JSON）
  → schema 校验（缺字段就重试，最多 2 次）
  → 模板渲染（确定性，版本可复现）
  → 打包 zip → 上传 → 预览 → 发布
```

**不建议让模型直接写 HTML/CSS**：风格漂移、无法校验、容易带 XSS。让模型只产出内容 JSON，渲染交给模板。

## 5. 大屏与遥控器

- `/screen`：SSE（`/api/rooms/:code/stream`）推送投票结果、抢答赢家、答题进度、计时、积分榜；
- `/remote`：讲师手机上的大按钮（开始投票/下一轮抢答/重置计时/切换大屏内容），用 `remoteToken` 鉴权；
- 配对：房间码 + 大屏 token（创建房间时生成，可撤销）；
- 断网兜底：大屏用 2 秒轮询，SSE 不可用自动降级。

## 6. 嵌入能力（API + 组件 + MCP）

### 6.1 REST（房间作用域，Bearer 鉴权）
```
POST /api/rooms                     建房间
GET  /api/rooms/:code/state         课堂状态
POST /api/rooms/:code/poll          发起/结束投票
POST /api/rooms/:code/buzz          开启/开始/重置
POST /api/rooms/:code/quiz/publish  发布答题
POST /api/rooms/:code/score         表现分
GET  /api/rooms/:code/report        课后报告（JSON/CSV）
POST /api/packages                  上传课程包
```

### 6.2 可嵌入组件
```html
<script src="https://host/embed.js" data-room="ABCD" data-widget="poll"></script>
```
- 渲染为 iframe，样式互不污染；
- 通过 postMessage 上报 `poll.result`、`buzz.winner`、`room.state`；
- 适合嵌到客户自己的 PPT 网页、内部门户、培训系统。

### 6.3 MCP
- HTTP JSON-RPC，Bearer token（带 scopes），审计日志；
- 首批 8–10 个原子工具，不要一次铺满：
  `room.create / room.state / poll.start / poll.stop / buzz.start / quiz.publish / score.adjust / report.export / screen.url / package.create`
- 典型用法：讲师助手说“发一个投票：今天讲得清楚吗”，MCP 执行并在大屏出结果。

## 7. 部署形态

- **局域网**：Node 单进程，房间数据落本地；钉钉登录不可用，走本地口令兜底；
- **公网（钉钉登录必需）**：需要 HTTPS 域名 + 钉钉回调白名单；API 可放 FC，课程包与状态放 OSS；
- **客户内网**：Docker 单容器，SQLite 存房间与讲师（比 JSON 更适合归档）。

## 9. 风险与待确认

- 钉钉应用（ClientId/Secret）、育钉组织 CorpId、回调域名、通讯录读权限；
- 上传课程包是同源 iframe，会继承后台权限：需独立子域或 sandbox，至少讲师鉴权；
- MCP token 泄露风险：只给最小 scopes + 审计 + 可撤销；
- 学员数据（姓名 + 手机后四位）属弱身份，报告导出需脱敏；
- 是否需要多班并行：v0.3 支持多房间但只做单讲师并发，避免过早做资源隔离。

## 10. 与现有系统的迁移

1. 现有 state.json 迁为默认房间 `ROOM0`；
2. 所有接口加 `room` 参数，缺省用 `ROOM0`；
3. 旧页面保留，逐步切到新入口；
4. 线上 gzzhike 与 FC 保持可用，新能力先本地跑通再部署。
