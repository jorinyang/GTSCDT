# 课程开发方法论（七步）

> 这是弈策AI研究院做一门企业 AI 课的固定流程，工具里的每个页面都对应其中一步。

## 1. 需求澄清
- 谁来讲、讲给谁、多少人、什么岗位、现有 AI 使用水平；
- 客户真正想解决的问题（不是"想听 AI"，而是"哪个环节卡住了"）；
- 场地与设备：会议室 / 工位 / 手机 / 台式机 / 网络。

**产出**：一页需求卡（人数、岗位、目标、约束、风险）。

## 2. 学习目标
分三层写，避免"了解 AI"这种无法验收的目标：
- **认知层**：能说清 AI 现在到哪一步、为什么；
- **框架层**：能把一个智能体拆成入口/模型/记忆/工具/能力/连接器；
- **实战层**：能在自己岗位上完成 6 个具体任务，并说明验收标准。

## 3. 模块设计
- 上午以"看懂"为主，下午以"做出"为主；
- 每个模块 45–75 分钟，中间必须有茶歇与切换；
- 每个小节只回答一个问题，配一页图或一次演示。

## 4. 题目设计（关键）
- 题目必须是**学员岗位上的真事**，不是抽象练习；
- 每题写清：背景、要交什么、做到什么程度算过关；
- 题面（给学员看的问题）与行动卡（输入→动作→产物→验收线）分开：题面在课件讲，行动卡在工作坊开始时发。

## 5. 评分设计
- 每关 = 产物质量 70% + 三问拆解 30%；
- 自动检查能做的（关键词、字数、结构）交给系统，判断类留给讲师；
- 评分规则提前写进系统，课堂上只做复核，不现场想标准。

## 6. 课堂机制
- 开场抽签分组，全天不变；
- 表现分 + 作业分合并为小组积分，现场公布；
- 投票、抢答用来拉回注意力，不为了热闹而热闹；
- 作业提交由讲师开关控制，避免提前泄露。

## 7. 交付资产
- 宣传页、课件、课堂后台、学员页、作业中心、素材包、评分表；
- 课后导出成绩与共性问题，形成下一场的改进项。
