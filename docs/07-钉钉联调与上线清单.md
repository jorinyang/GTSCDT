# 钉钉联调与上线清单（需要你配合）

> 目标：把「钉钉扫码登录」跑通，并决定公网部署方式。下面每一步都写清你在哪操作、我需要什么。

## 一、钉钉侧（你来操作）

1. 打开钉钉开放平台 → 创建「企业内部应用」（如果已有育钉组织下的应用可复用）。
2. 开通权限（缺一不可）：
   - 登录相关：`Contact.User.Read`（个人信息读权限）；
   - **成员信息读权限：`qyapi_get_member`** —— 用于通过 unionId 换 **userid**，并读取姓名、头像、部门、职位；
   - 如需部门同步：通讯录部门读取权限。

   > 现在应用缺 `qyapi_get_member`，所以登录后只能拿到昵称，拿不到 userid / 头像 / 部门。
   > 首页「个人信息」会显示提示和申请链接；接口 `/api/dingtalk/diag` 可随时查看权限状态。
3. 记录并给我：
   - `ClientId`（AppKey）
   - `ClientSecret`（AppSecret）
   - 育钉组织的 `CorpId`
4. 配置回调地址（完成公网部署后再填也可以）：
   `https://<你的域名>/auth/dingtalk/callback`
   并把该域名加入应用「重定向 URL」白名单。

> 凭证不要发在公开群；可以只写进服务器环境变量，或临时发我、我写进本机 env 后立刻删除。

## 二、部署侧（二选一）

### A. 局域网（最快，周五可用）
- 讲师机运行 `node server.mjs`；
- 钉钉扫码在局域网里**用不了**（回调要公网）；此时用 `LOCAL_TEACHER_PASSWORD` 本地口令登录。

### B. 公网（钉钉登录必需）
- 需要一台可公网访问的 Node 主机 + HTTPS 域名（或用 Docker：`docker build -t gtscdt .`）；
- 环境变量：
  ```
  PORT=8899
  SESSION_SECRET=<随机长串>
  PUBLIC_URL=https://<你的域名>
  DINGTALK_CLIENT_ID=...
  DINGTALK_CLIENT_SECRET=...
  DINGTALK_CORP_ID=...
  LOCAL_TEACHER_PASSWORD=<可选兜底>
  REQUIRE_AUTH=1
  ```
- 启动后把回调域名填进钉钉应用。

## 三、联调时我会做的验证

1. 访问 `/auth/dingtalk` 能跳到钉钉授权页；
2. 扫码后回调能换 token、拿到 unionId；
3. 讲师名单里匹配到人 → 发 Cookie → 跳 `/home`；
4. 首次登录的钉钉账号自动进讲师名单（角色默认「讲师」），不返回 403；
5. 若已开通 `qyapi_get_member`：保存 **userid / 姓名 / 头像 / 部门 / 职位**，首页个人信息可见；
6. 若未开通：首页显示「钉钉成员信息未取全」提示与申请链接，登录仍可用；
7. 退出/过期后再次访问 `/home` 会回登录页。

## 四、需要你确认的三件事

1. 公网域名与服务器是否已有？没有的话是否先用局域网 + 本地口令跑周五？
2. 钉钉应用是否已在育钉组织下创建？谁有管理员权限加白名单？
3. 讲师名单：先把要登录的几位姓名、手机号（用于匹配）、unionId（如果有）给我，我预置进 `/teachers`。

## 五、上线前检查

- [ ] `SESSION_SECRET` 不是默认值
- [ ] `REQUIRE_AUTH=1` 已开
- [ ] 钉钉回调地址与域名一致（https）
- [ ] 大屏/学员页在同一网络可访问
- [ ] 房间数据目录有备份策略
- [ ] 课后导出报告并清理测试数据
