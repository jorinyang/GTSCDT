# Game Theory Strategy Course Development Tools（弈策课程开发工具）

**GTSCDT** · v0.3

把一堂企业 AI 培训从「课前准备 → 开场 → 讲授 → 工作坊 → 交作业 → 评分 → 复盘」整条链路做成可运行的系统。
讲师用 PPT 讲课也能用，用本仓库的课件也能用；课堂互动、作业、评分、课程包、嵌入接口和 MCP 都是独立能力。

> 仓库原名 GTSICCDT，v0.2 起更名为 **GTSCDT**。本仓库是脱敏模板：客户名、讲师信息、接口地址、样例数据均为占位。

## 一、能力全景

### 1. 课堂层（以「房间」为核心）

| 能力 | 解决什么 | 入口 |
|---|---|---|
| 房间 | 一节课一个房间，学员、投票、答题、作业、积分都挂在房间上，互不串场 | `/rooms` |
| 操作台 | 讲师的全部课堂操作：投票、分组、抢答、答题、作业、表现分、学员、模型 | `/ops?room=CODE` |
| 大屏 | 投影只负责展示：投票结果、抢答赢家、答题进度、积分榜、倒计时 | `/screen?room=CODE` |
| 遥控器 | 讲师手机操作，不必回到电脑前 | `/remote?room=CODE` |
| 学员入口 | 学员扫码进入，姓名 + 手机后四位识别 | `/join?room=CODE` |
| 大屏实时 | SSE 推送，断线自动降级轮询 | `/api/stream` |
| 报告 | 课后汇总学员、小组、答题、作业，导出 CSV | `/report?room=CODE` |

### 2. 教学内容层

| 能力 | 解决什么 | 入口 |
|---|---|---|
| 课程包 | 任意 HTML 课程包上传后，套进统一框架播放（保留顶部导航与后台入口） | `/packages`、`/shell?pkg=` |
| AI 生成课程包 | 粘贴素材，模型出大纲，模板渲染成单文件课程包 | `/packages` 里的「AI 生成」 |
| 课程包模板 | 内容 JSON + 构建脚本，团队按模板产出 | `templates/course-package-template/` |
| 课件 | 内置 14 个视图的单文件课件（时间线、三层能力、六道题、路线图） | `/course` |
| 宣传页 | 单页招生/预热页 | `/promo` |

### 3. 身份与权限层

| 能力 | 解决什么 | 入口 |
|---|---|---|
| 讲师登录 | 钉钉 OAuth2 扫码（需应用凭证）或本地口令 | `/login` |
| 讲师管理 | 添加/删除讲师，角色：超管 / 讲师 / 助教 / 观察 | `/teachers` |
| 强制登录 | 开启后，后台页面跳登录、管理接口 401，大屏仍公开 | `REQUIRE_AUTH=1` |
| 学员识别 | 房间码 + 姓名 + 手机后四位，不要求学员注册 | `/join` |

### 4. 接口与集成层

| 能力 | 解决什么 | 入口 |
|---|---|---|
| 嵌入组件 | 投票/抢答/答题/积分小组件，嵌 PPT 网页或客户门户 | `/embed.js`、`/embed` |
| MCP | AI 助手直接操作课堂：建房、发投票、开始抢答、发布答题 | `/mcp`（JSON-RPC） |
| REST API | 房间、状态、投票、答题、作业、报告 | `/api/*` |

## 二、快速开始

```bash
cd templates
node server.mjs
```

打开：

- 房间管理 `http://127.0.0.1:8899/rooms`
- 课堂后台 `http://127.0.0.1:8899/ops?room=ROOM0`
- 大屏 `http://127.0.0.1:8899/screen?room=ROOM0`
- 遥控器 `http://127.0.0.1:8899/remote?room=ROOM0`
- 学员页 `http://127.0.0.1:8899/join?room=ROOM0`
- 课程包 `http://127.0.0.1:8899/packages`、播放 `/shell`
- 讲师管理 `http://127.0.0.1:8899/teachers`
- 报告 `http://127.0.0.1:8899/report?room=ROOM0`

可选环境变量：

| 变量 | 作用 |
|---|---|
| `PORT` | 端口，默认 8899 |
| `SESSION_SECRET` | 登录 Cookie 的 HMAC 密钥 |
| `LOCAL_TEACHER_PASSWORD` | 本地讲师口令（无钉钉时用） |
| `DINGTALK_CLIENT_ID` / `DINGTALK_CLIENT_SECRET` | 钉钉企业内部应用 |
| `DINGTALK_CORP_ID` | 组织校验与部门同步 |
| `ADMIN_DING_UNIONID` | 首个超管（可选） |
| `REQUIRE_AUTH` | `1` 开启强制登录 |
| `PUBLIC_URL` | 公网地址，用于钉钉回调 |
| `MCP_TOKEN` | MCP 访问令牌 |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE` / `DEEPSEEK_MODEL` | 模型评分兜底配置 |

## 三、功能详解（能力 · 怎么用 · 适用场景）

### 1. 房间

**能力**：把一节课隔离成独立状态；旧数据自动归入默认房间 `ROOM0`。房间码 4 位，避免 0/O/1/I。

**怎么用**：`/rooms` 填名称创建 → 自动进入操作台；四个入口（操作台/大屏/遥控器/学员）都带房间码；课堂结束不用删，下次新建即可。

**适用场景**：一天多班、连续几天培训、不同客户复用同一台机器。

### 2. 操作台 `/ops`

**能力**：四个标签——课堂管理、作业评分、在线答题、模型管理。

**怎么用**：
- 投票：填问题与选项（每行一个）→ 发起；学员手机投票，大屏实时出结果；
- 抽签分组：学员点抽签，按人数平均分配、每组不超上限（1–10 人）；分组可改名/删除/新增；
- 抢答：开启 → 开始（可多轮）→ 最快者胜出；大屏显示赢家；
- 表现分：按小组加减分；
- 学员管理：改名、改组、删除、清空，查看投票/抢答次数。

**适用场景**：所有课堂互动；没有课件、只用 PPT 时，这是讲师的唯一控制台。

### 3. 在线答题

**能力**：题库（选择/判断/填空/简答）→ 随机或顺序出题 → 按类设分 → 学员手机作答 → 自动判分；简答题由模型按参考答案打分。

**怎么用**：操作台「在线答题」→ 下载模板 → 填四个 sheet → 导入 → 设数量与分值 → 发布；学员页出现答题卡；提交后客观题立即判分，简答题模型评分；可结束、清空结果、清空题库。

**适用场景**：随堂测、上午知识点回顾、下午开场快答、培训后测验。

### 4. 作业评分

**能力**：六关矩阵、提交列表、自动判分（关键词/字数）、人工改分、AI 评分（按评分标准逐项给分并写依据）、导出 CSV。

**怎么用**：操作台「作业评分」→ 打开作业提交开关 → 学员在工作坊上传 → 讲师点行看详情 → 需要时点「AI 评分」→ 可再人工改 → 导出。

**适用场景**：下午工作坊六道题、课后作业批改、多组并行评分。

### 5. 工作坊计时与行动卡

**能力**：90 分钟倒计时（可暂停/重置），一键把「行动卡 + 素材下载」推送到所有学员页；大屏同步显示倒计时。

**怎么用**：操作台「工作坊」→ 设时长 → 开始计时 → 点「推送行动卡」；学员页出现任务卡与素材链接；结束时暂停或重置。

**适用场景**：工作坊、分组实操、限时挑战；PPT 讲课时替代课件里的计时器。

### 6. 大屏 `/screen`

**能力**：只读展示，讲师电脑操作不影响投影；投票条、抢答赢家、答题进度、积分榜、倒计时。

**怎么用**：副屏/投影打开 `/screen?room=CODE` → 全屏；不需要登录。

**适用场景**：教室投影、客户现场、线上直播推流画面。

### 7. 遥控器 `/remote`

**能力**：手机上的大按钮：发起/结束投票、开启/开始/关闭抢答、结束答题、开始/重置计时、推送行动卡。

**怎么用**：讲师手机打开 `/remote?room=CODE`；第一次投票可现场填问题与选项。

**适用场景**：讲师站在台下、边走边讲；不想回电脑前。

### 8. 学员页 `/join`

**能力**：加入房间、抽签、投票、抢答、答题、看行动卡与素材、上传作业（六类，确认后提交）。

**怎么用**：学员扫码或打开链接，填姓名 + 手机后四位；之后所有互动都在这一页。

**适用场景**：所有需要学员参与的环节；不需要装 App、不需要注册。

### 9. 课程包与框架

**能力**：上传任意 HTML 课程包，套进统一框架（顶部导航、后台入口、房间码）；AI 可把素材生成课程包；模板支持团队标准化产出。

**怎么用**：
- 上传：`/packages` 选 HTML → 上传 → 预览 → `/shell?pkg=ID` 播放；
- AI 生成：粘贴素材 → 生成（约 10–30 秒）→ 预览；
- 模板：`templates/course-package-template/example.json` 改内容 → `node build.mjs example.json out.html`。

**适用场景**：不同客户不同课件；销售/讲师自己改内容；把旧 PPT 导出的 HTML 快速套壳。

### 10. 讲师与权限

**能力**：钉钉扫码登录（配置应用后）、本地口令兜底、角色分级、强制登录开关、讲师名单管理。

**怎么用**：`/teachers` 添加讲师与 unionId → 讲师打开 `/login` 钉钉登录；没有钉钉时用 `LOCAL_TEACHER_PASSWORD`；要强制登录设 `REQUIRE_AUTH=1`。

**适用场景**：多讲师共用一套系统；客户现场要求登录；公网部署。

### 11. 报告

**能力**：课后一页看全：学员、投票、抢答、作业数、小组积分、答题得分；可下载 CSV。

**怎么用**：`/report?room=CODE`，或从房间列表进入。

**适用场景**：课后复盘、给客户交付课堂数据、下一场改进依据。

### 12. 嵌入组件与 MCP

**能力**：
- `<script src=".../embed.js" data-room="CODE" data-widget="poll"></script>` 嵌入投票/抢答/答题/积分；
- MCP：`/mcp` JSON-RPC，10 个工具，AI 助手可直接发投票、开始抢答、发布答题、取报告。

**怎么用**：嵌入到 PPT 网页或客户门户；MCP 用 `Authorization: Bearer <MCP_TOKEN>` 调用。

**适用场景**：客户已有系统不想换；AI 讲师助手自动运营课堂。

## 四、一堂课怎么用（按课程顺序）

完整版见 [docs/06-课堂使用说明-按课程流程.md](docs/06-课堂使用说明-按课程流程.md)。

1. **课前**：建房间 → 打开大屏 → 讲师登录 → 上传课程包 → 导入题库 → 关闭作业提交 → 模型管理里测试连通性；
2. **开场**：学员扫码加入 → 抽签分组 → 讲积分规则 → 大屏亮起；
3. **上午讲授**：每个模块穿插投票（认知摸底）、抢答（拉回注意力）、在线答题（随堂测）；
4. **下午工作坊**：推送行动卡 → 开始 90 分钟计时 → 学员按六关做题 → 随时看大屏进度；
5. **提交与评分**：开作业提交 → 学员上传 → 讲师用作业评分 + AI 评分复核；
6. **复盘**：结束答题/投票 → 打开报告 → 导出 CSV → 公布积分与发奖；
7. **课后**：保留房间数据或归档；下一场新建房间。

## 五、部署

- **局域网（现场推荐）**：讲师机 `node server.mjs`，学员连同一 Wi-Fi，访问 `http://<讲师机IP>:8899/join?room=CODE`；
- **公网（钉钉登录必需）**：需要一台可公网访问的 Node 主机 + HTTPS + 钉钉回调白名单；也可用 Docker：
  ```bash
  docker build -t gtscdt .
  docker run -p 8899:8899 -e SESSION_SECRET=... -e DINGTALK_CLIENT_ID=... gtscdt
  ```
- 钉钉开放平台：创建企业内部应用，开通「登录」与「个人信息读权限」，回调填 `https://<域名>/auth/dingtalk/callback`；
- 数据：房间与上传在 `templates/data/`，已在 .gitignore 中忽略。

## 八、已知边界

- 钉钉登录代码已就绪，**真实扫码需要应用凭证与公网回调域名**，本仓库未内置凭证，也未完成真实联调；
- 公网部署需要 Node 运行环境，当前静态托管（OSS）只能放页面，不能提供房间/登录/MCP；
- 学员身份是「姓名 + 手机后四位」的弱身份，不适合对身份要求严格的场景；
- 无头浏览器截图在本机环境不可用，页面只做了加载与接口验证，版式请在浏览器里复核。
