# 公网部署说明（gzzhike.cn）

> 结论先说：**阿里云 OSS 只能放静态文件，跑不了 v0.3 后端。** 房间、讲师登录、课程包上传、MCP、SSE 都需要一个常驻 Node 进程。

## 一、为什么 OSS 不行

OSS 是对象存储 + 静态网站托管，只能返回 HTML/CSS/JS/图片；它不会执行 Node 代码，也没有可写的本地状态目录。

v0.3 运行时需要：

- 常驻 HTTP 服务（房间状态、投票、抢答、答题、作业）；
- 可写的数据目录（`templates/data/`，房间状态与上传文件）；
- SSE 长连接（大屏实时）；
- 登录 Cookie 与钉钉 OAuth 回调。

这些 OSS 都不提供。把页面放 OSS，打开 `/ops` 会看到页面，但任何操作都会 404。

## 二、可选方案

### 方案 A：ECS / 轻量应用服务器（推荐）

一台最低配 Linux（1 核 2G 足够 20 人课堂）。

```bash
# 服务器上
git clone https://github.com/jorinyang/GTSCDT.git
cd GTSCDT
cp deploy/.env.example deploy/.env   # 填好钉钉与 secret
docker compose -f deploy/docker-compose.yml up -d --build
```

- 域名解析：`gzzhike.cn` A 记录指向服务器公网 IP；
- HTTPS：用 certbot 申请证书，Nginx 配置见 `deploy/nginx.conf`；
- 钉钉回调填 `https://gzzhike.cn/auth/dingtalk/callback`；
- 数据落在 `deploy/data/`（compose 已挂载），备份这个目录即可。

### 方案 B：OSS 放静态页 + 函数计算跑接口

- 页面（`screen.html`、`remote.html`、`login.html` 等）传 OSS；
- 接口迁到阿里云 FC；
- 现阶段 FC 版本是 v0.2（Python），**没有房间/登录/MCP**；要补齐需要移植 v0.3 接口（约 1–2 天），且 SSE 要降级为轮询。

### 方案 C：OSS 只做宣传页/课程包预览

- `promo.html` 与打包好的课程包可以放 OSS；
- 课堂运营仍走局域网或 ECS。

## 三、钉钉应用配置（需要你在开放平台操作）

1. 应用：企业内部应用，拿到 `ClientId` / `ClientSecret`；
2. 开通权限：登录与个人信息读权限（`Contact.User.Read`）；需要部门同步再开通讯录部门读权限；
3. **重定向 URL** 填：

   ```
   https://gzzhike.cn/auth/dingtalk/callback
   ```

   （如果控制台要求填"回调域名"，填 `https://gzzhike.cn`，再在重定向 URL 里填完整路径。）
4. 把 `gzzhike.cn` 加入应用的可信/安全域名（如果控制台有这一项）。

服务端环境变量：

```
PUBLIC_URL=https://gzzhike.cn
DINGTALK_CLIENT_ID=...
DINGTALK_CLIENT_SECRET=...
DINGTALK_CORP_ID=...
SESSION_SECRET=<随机长串>
REQUIRE_AUTH=1
```

## 四、部署后验证

1. 打开 `https://gzzhike.cn/api/ping` → `{"ok":true}`；
2. 打开 `https://gzzhike.cn/login` → 点「钉钉登录」→ 能跳到钉钉授权页；
3. 扫码后回到 `/ops`，`/teachers` 里能看到该讲师；
4. 建房间 → 大屏 → 手机遥控器 → 学员页各试一遍；
5. 钉钉应用后台看授权回调是否报错。

## 五、安全提醒

- 钉钉 `ClientSecret` 只放服务器环境变量，不进仓库、不发群；
- `SESSION_SECRET` 必须换成随机长串；
- 公网务必开 `REQUIRE_AUTH=1`，否则后台接口裸奔；
- 课堂结束可停容器或改房间；数据目录定期备份。
